                     as a scratch output. In subsys/net/lib/http/http_server_http2.c,
                     handle_http2_static_fs_resource() passed &client->data_len as the file_size
                     out-parameter of http_server_find_file(). client->data_len is the count of
                     unprocessed bytes remaining in the fixed-size per-connection receive buffer
                     client->buffer[CONFIG_HTTP_SERVER_CLIENT_BUFFER_SIZE] (256 bytes by default),
                     an invariant every frame handler and the socket receive path rely on. Serving
                     any static file therefore replaced that bounded value with the file's on-disk
                     size, and nothing resets it afterwards.

                     The defect is reached by an unauthenticated HTTP/2 GET for any file under the
                     web root, in applications that register a static-filesystem resource
                     (HTTP_RESOURCE_TYPE_STATIC_FS) with CONFIG_FILE_SYSTEM=y;
                     CONFIG_HTTP_SERVER_VERSION_2 is enabled by default and no TLS or credentials
                     are required on this path. Once client->data_len exceeds the buffer size, the
                     frame dispatch loop in subsys/net/lib/http/http_server_core.c keeps parsing
                     past the end of the received data, and the peer controls the bytes at
                     client->cursor, so it can choose which fabricated frame the state machine
                     consumes next by appending bytes after its request.

                     The inflated length defeats the only guards on the buffer.
                     parse_http_frame_header() and the per-frame handlers read and skip up to a
                     24-bit frame length beyond the buffer (out-of-bounds read); the compaction
                     memmove(client->buffer, client->cursor, client->data_len) at the end of request
                     handling copies the file-size number of bytes into the 256-byte buffer,
                     overflowing the rest of struct http_client_ctx — including the
                     current_detail/current_stream pointers, the parser_settings function-pointer
                     table and the inactivity_timer work handler — and the adjacent client contexts

                     bounds.
